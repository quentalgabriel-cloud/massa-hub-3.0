As migrations são aplicadas no banco Supabase via `supabase db push` (ou `supabase migration up` em ambiente local com `supabase start`); os arquivos seguem a convenção de nome `YYYYMMDDHHMMSS_descricao.sql` e são executados em ordem cronológica — nunca edite uma migration já aplicada, crie uma nova. **Atenção:** as políticas de Row Level Security (RLS) incluídas aqui são placeholders permissivos adequados para desenvolvimento; antes de ir para produção, substitua-as por políticas que validem `auth.uid()` contra `autor_id` e `criador_id`, garantindo que cada usuário só acesse e modifique seus próprios registros.
