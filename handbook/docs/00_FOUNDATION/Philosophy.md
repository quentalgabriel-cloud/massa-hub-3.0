# Philosophy — Como FeelWorks Pensa

## Propósito

Este documento explica **a lógica subjacente** às decisões de FeelWorks.

Não é "o que fazemos", é **"por que pensamos desse jeito"**.

Audiência: Time de produto, engenharia, design (decisões estratégicas).

---

## Pilar 1: Contexto é Tudo

### A Realidade

Toda decisão em FeelWorks depende de contexto.

- Qual é a oportunidade? (qual cliente, qual briefing?)
- Quem é o assessor? (experiência, especialidade?)
- Qual é o histórico? (já trabalhou junto antes?)
- Qual é a urgência? (meta em 1 mês ou 3 meses?)

### Implicação

**Não existem decisões genéricas em FeelWorks.**

Cada matching, cada sugestão, cada ação é contextualizada.

UX precisa sempre revelar contexto. Dashboards sem contexto são ruído.

---

## Pilar 2: Dados Existem para Decisões

### A Realidade

Dados que não levam a uma ação são desperdício.

Não coletamos "para depois ver". Coletamos porque sabemos que pergunta vamos responder com isso.

### Implicação

- Métrica sem ação = não coletar
- Coleta sem análise = não fazer
- Análise sem decisão = não publicar

Cada número em FeelWorks responde a uma pergunta clara que alguém precisa fazer.

---

## Pilar 3: IA Reduz Trabalho, Não Autonomia

### A Realidade

Assessor não quer robô decidindo no lugar dele. Quer ferramenta economizando seu tempo.

### Implicação

Assistência, não substituição.

- IA estrutura o briefing
- Assessor valida e refina
- IA sugere candidatos
- Assessor escolhe
- IA acompanha progresso
- Assessor toma decisão

**Pessoa no loop sempre.**

---

## Pilar 4: Informação Precisa Produzir Ação

### A Realidade

Informação sem ação é ansiedade.

("Tenho 3 oportunidades esperando, mas não sei o que fazer com elas" = ansiedade operacional.)

### Implicação

Cada informação em FeelWorks vem com um **próximo passo claro**.

- Vê oportunidade → sabe como candidatar
- Recebe feedback negativo → sabe como iterar
- Vê reputação baixa → sabe que ações a melhoram

Nunca deixamos alguém com informação mas sem bussola.

---

## Pilar 5: Conhecimento Nunca Pertence a Uma Pessoa

### A Realidade

Se o knowledge está só na cabeça de um assessor, é frágil.

A empresa perde se a pessoa sai. O assessor fica preso.

### Implicação

**Conhecimento é sempre capturado e socializado.**

- Padrões de oportunidade → template
- Lições aprendidas → playbook
- Decisões importantes → decision record
- Relacionamentos → mapeados no sistema

Ninguém é insubstituível. Tudo é reproduzível.

---

## Pilar 6: Toda Interação Gera Memória

### A Realidade

Cada conversa, cada oportunidade, cada feedback é aprendizado.

Se perder isso, perdemos insight.

### Implicação

**Sistema aprende continuamente.**

- Assessor rejeita candidato X para marca Y → marca Y provavelmente quer X de novo
- Candidato A aceitou oportunidade de 50k → próxima de 40k ele vai rejeitar
- Padrão: marcas de tech querem creators com tech background

Memória é gerada automaticamente, sem extra work do usuário.

---

## Consequência Prática

Essas 6 filosofias mudam **tudo**:

- **Design**: Cards com espaço (contexto visível), baixa densidade (não overwhelm)
- **Product**: Workflow em vez de cadastro (contexto guia interação)
- **Engineering**: Logging de contexto (memória vira dataset)
- **IA**: Sugestão contextualizada (não recomendação genérica)
- **Métrica**: Ações tomadas (não dados coletados)
